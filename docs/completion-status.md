# codexm 기능과 완료 검증 상태

2026-10-13, 로컬 macOS. 최신 후속 구현은 0.5.1이며 다른 장비 배포·Release/npm/tap
게시는 이번 범위에 포함하지 않는다. 구현·격리 시험·실제 앱 표시와 미완료 요구를 구분한다.

| 요구 | 구현과 확인 | 남은 범위 |
|---|---|---|
| 공식 Codex를 그대로 사용 | 독립 실행 파일·공식 엔진·계정별 인증 홈; 공식 CLI를 감싸지 않음 | 호스트 업데이트 뒤 호환 진단 필요 |
| 일반 작업·새 작업·기존 대화 | native SQLite 읽기 전용 목록, 같은 ID 등록·resume, 추가 지시·승인 | 원래 GUI writer 소유권은 보존 |
| 계정과 정책 관리 | 추가·재로그인·취소, 관리자/기본/예비 계정과 우선순위 편집 | 실제 운영 계정 로그인은 시험하지 않음 |
| 한도 교체·예비 계정 복귀 | 영속 큐, 동시 실행 보호, 상위 계정 확인·600초 복귀 | codexm 소유 worker에서 실행 |
| 데몬·강제 종료 복구 | launchd/systemd, observer upgrade·rollback, 같은 worker 채택 | Linux 실장비 배포는 이번 범위 밖 |
| 기록·Discord | 전체/세션 로그, 실행 구간과 한도 관측; 전체 계정 5h 알림·중복 방지 | 관측 %는 계정 전체이며 세션 소비량 아님 |
| 앱 내 관리 패널 | 실제 MCP·native 엔진의 격리 패널 시험, 사용자 사진에서 실제 앱 표시 | 소개 화면의 직접 버튼 노출·클릭은 미확인 |
| 명령형 진입 | `@codexm manage/accounts`, 전용 스킬 2개; 공식 CLI·앱 엔진 발견·열기 시험 | 새 명령의 실제 GUI 호출은 미확인 |
| 원래 GUI 채팅의 투명한 계정 교체 | 한도 감지와 writer 해제 뒤 동일 ID 인계까지 구현·시험 | **미완료: 선택한 GUI writer 해제·대화별 인증 API가 없음** |

명령 스킬은 한 번의 모델 턴을 사용해 화면을 연다. 이후 UI 조작·감시·복구는 모델을
호출하지 않는다. 새 native slash 명령으로 안내하지 않는다. 플러그인 선택이나 열기만으로
현재 채팅이 등록·실행되지 않으며, Try now는 작업 시작 버튼이 아니다.

관리 패널의 새 작업은 codexm이 소유한 공식 CLI worker에서 실행한다. 이미 원래 GUI가
실행 중인 대화는 등록해 감시할 수 있지만, GUI가 writer를 놓기 전에는 계정 인계를 대기한다.
이 둘을 동일한 완료 상태로 표시하지 않는다. 공개 API의 제한을 잠금 삭제·전역 로그인
교체·GUI 강제 종료·앱 패치·새 대화 fork로 우회하지 않는다.

실행한 검증은 [GUI·명령 기록](native-gui-validation.md), 인계 제한은
[공식 API 경계](gui-handoff-boundary.md), 사용법은 [플러그인 안내](local-plugin.md)를 따른다.
전체 목표는 원래 GUI 대화의 투명한 계정 교체까지 요구하므로 이 표만으로 완료 처리하지 않는다.
