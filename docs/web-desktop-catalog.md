# GUI와 웹의 공통 대화 목록

웹은 설정된 `runtime.shared_codex_home`의 원본 대화를 읽는다. 계정 선택은 실행 인증을
고르는 기능이며, 조회할 대화 저장소를 다른 곳으로 전환하지 않는다.

## 읽기 기준

- 최신 버전의 `state_*.sqlite`를 `mode=ro`, `query_only`, live WAL로 읽는다.
  `immutable=1`, rollout 스캔/복구, DB 마이그레이션은 사용하지 않는다.
- GUI의 `.codex-global-state.json`에서는 프로젝트 목록/ID 대응, 기존 수동 배정,
  명시적인 프로젝트 없음, 현재 GUI 소유자의 작업 폴더 힌트와 제목을 반영한다.
  인증 정보와 다른 GUI 상태를 웹에 반환하지 않으며 GUI 설정 파일에 쓰지 않는다.
- native 프로젝트 연결을 우선하고 기존 GUI 수동 배정을 적용한다. 자동 폴더 연결은
  정확한 root 경로 또는 저장된 root 힌트로 한정한다. 상위 폴더 아래라는 이유만으로
  서로 다른 저장소를 같은 프로젝트로 묶지 않는다. 중복 root는 GUI 순서로 결정한다.
- 기존 GUI 프로젝트는 원래 ID와 순서로 표시하고 native ID를 공식 변경 요청에만
  변환한다. native에만 존재하는 프로젝트는 프로젝트 선택기에서 ‘GUI 목록 외’로 표시한다.
- GUI 기본 이력의 interactive 대화와 고정된 실행 대화를 표시한다. 자동 관리용 exec,
  빈 초안, attached/subagent 대화는 기본 목록에서 제외하지만 원본은 보존한다.
- 고정은 native Pinned 섹션과 순서를 따른다. 예전 private 웹 고정 파일은 원본을
  바꾸는 데 사용하지 않는다. 고정/해제는 `thread/section/move`로 명시적으로 처리한다.

전체 목록은 native 최근 사용 시각과 ID를 사용한 keyset 커서로 페이지를 구성한다.
고정 목록은 native 고정 섹션의 순서를 유지한다. 커서는 검색, 프로젝트와 보관 여부에 묶인다.
기존 공식 `thread/list` recency 커서가 특정 과거 페이지에서 멈춘 경우에도 이력을
빠뜨리거나 자동 복구를 실행하지 않는다. 브라우저 갱신은 이미 펼친 페이지를 모두
다시 읽어 GUI에서 보관·이동·삭제한 대화가 오래된 목록에 남지 않게 한다.

웹은 로컬 MongoDB에 마지막으로 완성한 목록을 보관한다. 시작할 때 복구한 목록을
바로 사용하고, 로그인 또는 채팅 진입과 약 1분 주기로 원본을 비동기 갱신한다.
고정·이동·보관 변경을 확인한 뒤에는 새 목록을 반영한다. 동시 요청은 같은 갱신을
공유하고, 원본 읽기에 실패하면 마지막으로 확인한 목록을 유지한다.

본문은 같은 ID로 공식 `thread/read`, `thread/turns/list`, items API를 호출한다.
조회는 resume·새 prompt·소유권 인계를 실행하지 않는다. 외부 GUI/CLI가 소유한 작업의
직접 개입과 계정 변경 제한은 그대로 적용한다.

열어 본 대화와 스크롤 위치는 브라우저 탭의 메모리에 보관한다. 다시 열면 읽었던
페이지를 먼저 표시하고, 서버는 이력 버전과 턴별 변경을 확인해 달라진 본문만 보낸다.
대기열·승인·작업 상태는 별도로 갱신한다. DDP가 끊긴 동안에는 화면과 초안을 유지하고,
재연결 후 기존 로그인으로 다시 인증해 갱신을 이어간다.

채팅 메뉴의 **채팅 파일**에서 해당 대화의 Codex 생성 파일을 받거나 작업 폴더
기준의 경로를 등록할 수 있다. 등록한 사본은 웹의 비공개 상태에 보관한다. 해당
채팅의 링크를 열 때는 로그인 세션을 확인한다. PNG·JPEG·GIF·WebP는 본문에서
미리 볼 수 있고 HTML과 기타 파일은 다운로드한다.

웹 전용 실행에서 채팅 목표를 펼치면 일시 정지, 재개, 삭제를 실행할 수 있다. 이전
계정의 한도로 멈춘 목표는 계정을 선택하고 재개한다. 원래 목표와 예산은 같은 채팅에
유지된다. 런타임이 마지막 완료 턴의 예측 이벤트를 제공하면 빈 작성창에 표시한다.
Tab은 제안 문장을 작성창에 넣는다. 이력 조회는 예측을 새로 요청하지 않는다.

작업 상태 갱신은 목록 페이지 조회와 독립적이다. 한 번의 읽기 전용 writer 확인을
브라우저가 공유한다. 현재 writer가 확인된 채팅의 원본 JSONL 끝에서 제한된 범위의
턴 시작·종료 이벤트만 읽는다. 열린 창이 있다는 사실만으로 진행 중이라고 표시하지 않는다.
웹 실행의 작성 중 응답은 공식 이벤트에서 받아 브라우저로 보내며, 별도 메시지로 저장하지 않는다.

## 검증

- 합성 데이터에 GUI 이전 ID·native ID, 명시 배정·projectless·원격 호스트, 겹치는 root,
  exec 고정·attached/subagent·보관·여러 페이지를 섞어 ID 누락/중복과 읽기 보존을 검사한다.
- 실제 장비에서는 GUI 도구의 모든 이력 페이지, 고정 순서, 보관, 프로젝트 목록을 수집해
  웹 bridge의 전체 페이지와 대조한다. 기존 프로젝트 배정도 확인한다. GUI 도구가
  프로젝트 문맥을 반환하지 않는 과거 대화는 폴더 연결 결과와 구분해 기록한다.
- 실제 본문 조회는 모델 요청이나 쓰기 없이 검사하며, 원본 DB 내용과 진행 중 writer의
  프로세스·잠금이 보존되는지 확인한다. 실사용 제목·ID·경로·대화는 private 검증 자료에만 둔다.
- 배포는 matching CLI/TUI와 웹을 새 immutable 버전에 설치한다. 웹 소유 작업이 없는지
  확인하고 웹 서비스만 HTTPS Origin으로 재시작한다. 기존 GUI/CLI·공유 tmux는 보존한다.

GUI 메타데이터는 내부 형식이므로 버전 변경으로 해석할 수 없으면 명시적인 오류를
표시한다. 파싱 실패나 DB 읽기 실패를 빈 목록으로 처리하거나 원본을 고치지 않는다.
