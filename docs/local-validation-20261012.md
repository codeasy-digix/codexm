# 로컬 실행 검증 (2026-10-12)

검증 장비는 macOS ARM64다. 원본 프로젝트의 동시 변경을 보존하고 별도 worktree와
설정·상태 폴더에서 시험했다. 다른 장비에 설치하지 않았으며 배포 파일은 로컬에서만 준비한다.

| 확인한 동작 | 결과 |
| --- | --- |
| 전체 Go 회귀 검사 | `go test -race ./...`, `go vet ./...` 통과 |
| 공식 엔진 worker/세션 시험 | 빈 대화 이름·rollout 저장, 동일 ID의 계정 교체, writer lock, 목표 상태·예산·누적 사용량 유지 |
| 일시 중지된 세션 열기 | 재개하지 않고 화면 연결 가능. 실행 예약의 paused 대기 오류 수정 |
| 관리자 TUI 실제 PTY | 입력 초점·작성 중 내용 유지한 채 ↑↓ 사용 가능 |
| 공식 Codex 0.162.1 실제 PTY | 중지한 실행의 화면 열기 1.04초. 초기 CR 주입 후 새 입력이 첫 prompt 줄에 표시됨 |
| 공용 데몬 강제 종료 | 시험용 프로세스만 SIGKILL, 5.22초 후 새 PID로 복구 |
| 의도한 데몬 중지 | `codexm daemon stop` 후 감시 주기가 지나도 중지 유지. start로 감시 재개 |
| 기본 계정 선택 | 시험 설정에서 account-secondary → account-work 저장. 공식 기본 auth와 부모 셸은 유지 |
| 모델 호출 | 위 실제 화면·복구 시험의 관리자 호출 0. 작업 지시를 보내지 않음 |
| 준비한 배포 파일 | macOS/Linux ARM64/AMD64 컴파일. macOS ARM64만 실제 실행 |

실제 PTY 시험은 터미널 프로토콜로 공식 UI를 실행해 입력 줄과 문자 위치를 검사했다.
macOS Terminal 앱의 화면 자동 확인은 도구 접근 제한으로 수행하지 않았다.
1.04초는 최근 계정 확인을 재사용한 시험값이며 큰 대화·네트워크·터미널 앱 시작 시간의
상한은 아니다. 오래되거나 불명확한 계정 한도는 다시 확인한다.

시험 supervisor `codexm-product-test-ui`, 작업별 tmux, 공용 데몬 시험 감시 세션과
복사한 시험 인증은 검사 후 정리했다. 원본 대화·목표 본문·인증 정보는 출력하지 않았다.

이전 기능 보존 목록은 [이동 점검](migration.md), 게시하지 않은 패키지 준비는
[배포 구조](distribution.md)를 따른다.

## 최종 소스에서 추가 확인

- 공식 worker/writer-lock/동일 대화 계정 교체·완료/중지 goal 열람은 0.162.0에서도 통과했다.
- 별도의 공용 daemon 0.162.1 시험은 부모와 app-server의 시험 PID를 함께 종료해
  15.27초 뒤 복구됐고 stop 상태를 유지했다. 감시와 시험 daemon은 정리했다.
- 별도의 실제 PTY 입력 큐 시험에서는 시작 전 LF를 제거하고 실행 후 새 입력을 보존했다.
  모의 연결 준비 포함 1.45초이며 긴 대화의 총 연결 시간 측정은 아니다.
- 공식 npm 설치 0.160.0의 native package를 직접 찾아 protocol/hash를 검증하고
  임시 엔진으로 보관했다. Node launcher와 계정 controller는 실행하지 않았다.
- Go race/vet, 독립 installer의 다운로드 실패·기존 release 충돌·서로 다른 로컬
  개발 빌드 보존 검사가 통과했다. .home의 Codex 회귀 검사 50개(옵트인 1개 제외)도 통과했다.
- 제품 소스 변경은 commit/push하되 Release·tag·npm·tap 게시와 실행 중인 기존
  supervisor의 교체는 하지 않는다. 현재 설치의 0.1.2는 그대로 유지한다.
