# 0.6.1 계정 등록 삭제 검증

사용자가 선택한 범위는 codexm 등록 삭제이며 로그인 파일과 대화 기록은 보존한다.
웹·로컬 플러그인의 계정 카드에 확인 대화상자를 추가했고 CLI는
`codexm account NAME --remove`로 같은 Go 정책을 사용한다.

`account_registry.removed`는 보존된 계정 홈의 자동 재발견을 막는다. 우선순위에서 해당
별칭을 제거하고 예비 역할은 비우며, 관리자·진행 중 로그인·배정된 작업·전환 대상 계정은
삭제하지 않는다. 끝난 작업과 과거 실행·목표 예산은 수정하지 않는다. 공용 native 로그인도
그대로 두며 같은 별칭의 명시적 등록 또는 검증된 재로그인으로 복원한다.

삭제는 현재 설정 revision을 요구한다. 온라인은 supervisor의 dispatch gate와 durable
operation ID를 사용하고, 오프라인은 supervisor lease와 읽기 전용 작업 검사를 사용한다.
새 작업 생성과 비동기 한도 조회 뒤 계정 배정도 같은 삭제 경계에서 다시 검사한다.
한도 이력에 남은 계정이 플러그인 카드로 재생성되는 문제는 등록 목록을 기준으로 수정했다.
명시적 알림 대상 목록의 의미는 유지하면서 등록 해제 계정의 새 한도 조회·알림은 제외한다.

실행한 검사는 다음과 같다.

- `go test -race -p 4 ./...`, `go vet ./...` 및 웹 TypeScript·Node 검사.
- 로그인 파일·native auth 링크·대화 보존, 마지막 worker 제거, 관리자·작업·전환 대상·
  로그인 잠금·오래된 revision 거부, 삭제/작업 생성/자동 배정 경합과 중복 operation 재생.
- 검증된 재로그인의 등록 복원과 설정 저장 실패 시 auth rollback.
- 실제 공식 엔진의 빈 격리 로그인 시작·취소, 임시 native 대화·paused goal 및 예산 보존.
- 실제 Meteor/Chromium의 삭제·취소·관리자/사용 중 계정 거부, 다른 탭 반영과 웹/브리지
  재시작 후 유지. 실제 stdio MCP 패널에서도 삭제와 로그인 파일 보존을 확인했다.

초기 병렬 race 실행에서 기존 로그인 helper의 3초 시작 제한이 초과되어 패키지 동시 수를
4로 제한한 전체 검사로 확인했다. 로그인 종료 시 setup 취소 전달보다 engine 초기화가 먼저
끝나는 경합도 발견하여 lifetime 취소를 직접 검사하도록 수정했다. 모델 호출은 하지 않았다.
private 증거와 설치 전 유효한 DB 백업은 각 머신의
`~/.local/state/codexm/validation/account-remove-20261022/`에 보관한다.

## TUI 대화 아코디언 가능 여부

현재 관리 TUI는 대화를 공식 Codex의 별도 터미널로 연다. codexm 자체에 웹과 같은 대화
영역을 구성하면 도구 출력·처리 기록·오류 본문을 제목과 건수로 요약하고 마우스로 접고
펼칠 수 있다. 사용하는 Bubble Tea v2는 [마우스 이벤트와 클릭·휠 모드](https://github.com/charmbracelet/bubbletea/blob/main/UPGRADE_GUIDE_V2.md)를 지원한다.
항목 ID별 펼침 상태, 스크롤 좌표와 클릭 영역, 창 크기 변경 후 영역 갱신을 관리하며
Enter/Space 조작도 함께 제공할 수 있다. 최종 답변과 응답 대기 상태는 바로 보이게 두는
구성이 적절하다. 이 버전의 구현 범위는 계정 등록 삭제이며 TUI 대화 영역 개편은 별도다.
