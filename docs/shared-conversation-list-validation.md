# 전체 Codex 대화 목록: 2026-10-12 로컬 검증

0.2.1은 관리 DB에 등록한 작업뿐 아니라 공식 Codex SQLite의 모든 대화를 기본
TUI와 `codexm session list`에 표시한다. 관리 작업은 같은 대화 ID와 합쳐 중복을
제거한다. 목록 조회는 가져오기·소유권 변경·대화 재개·모델 호출을 수행하지 않는다.

공식 DB는 `mode=ro`, 연결별 `query_only(1)`, 1초 busy timeout으로 읽는다.
`immutable`을 사용하지 않아 실행 중인 writer의 WAL을 함께 읽는다. 대화 제목과
폴더·모델·토큰 등 목록 메타데이터만 조회하고 턴·첫 지시·목표 원문은 조회하지 않는다.
계정과 로그는 codexm DB에 남는다. native DB에는 테이블 추가나 마이그레이션이 없다.
버전 숫자로 최신 `state_*.sqlite`를 선택하고 실제 컬럼을 확인하며 선택 필드는
없어도 읽는다. 필수 컬럼이 다른 스키마에는 오류를 표시하고 DB를 변경하지 않는다.
TUI는 일시적인 조회 오류 중 마지막 목록을 유지한다.

검증 결과:

- `go test -race ./...`, `go vet ./...`, `git diff --check` 통과.
- 공식 DB/WAL 파일 해시가 읽기 전후 동일하고 UPDATE/CREATE가 거부됨.
- 열린 WAL writer의 미커밋 변경은 제외하고 커밋한 새 대화는 다음 조회에 표시됨.
- SQLite 버전 9/10 선택, 선택 컬럼 누락, 알 수 없는 필수 스키마, DB 부재 검증.
- 설치 전 Codex 없음·실행 실패 시 안내를 출력하고 새 설치 경로를 만들지 않음.
  기존 설치 링크 보존과 다운로드/해시/충돌 처리 회귀 검사도 통과.
- 실제 이 Mac의 native SQLite 대화 **568개**를 모두 표시하고 관리 작업 **5개**를
  중복 없이 합침. 보관 대화 **45개**도 포함. CLI 실행부터 JSON 해석까지 약 0.63초.
  검증 출력에는 실제 대화 제목·지시·목표 원문을 남기지 않음.
- 공식 엔진 0.162.1 격리 통합 검사: 외부 native API에서 만든 빈 대화가 자동 등록
  없이 목록에 표시되고 기존 작업의 writer lock과 계정/목표 설정이 유지됨.
- 최종 실행 파일의 실제 PTY 검사: 기본 전체 목록, 입력 포커스와 초안, 방향키
  선택, 공식 TUI 연결 확인. 중지한 빈 대화를 여는 데 **1.26초**, 초기 CR이 입력창에
  줄바꿈을 만들지 않음. 기본 native 로그인 유지, 관리자 모델 호출 **0회**.
- 임시 supervisor·worker tmux와 복사한 인증을 정리함. 다른 장비와 배포 레지스트리는
  변경하지 않음. 실제 상태/검증 자료는 Git 밖의 `~/.local/state/codexm/validation/`에 둠.

처음 대화를 열 때 계정을 선택하며 공식 TUI에는 동일한 thread ID를 연결한다.
이미 등록한 대화는 저장한 계정을 사용한다. 다른 프로세스의 writer lock은
기존 소유권 보호를 따른다. 과거 대화의 사용 계정을 추정하지 않으며 codexm 관리
로그는 등록 이후부터 관측한다.

이번 소스는 배포 준비 범위다. release/tag/npm/tap 게시와 다른 장비 설치는 하지 않는다.
