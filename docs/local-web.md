# 로컬 채팅 웹

선택적 Meteor + React 화면이다. 기본 CLI/TUI와 macOS 메뉴 앱은 웹·Node 없이
그대로 사용한다. 웹은 **같은 머신의** 채팅과 프로젝트를 보여주며, 다른 장비의
이력을 동기화하거나 가져오지 않는다.

## 화면과 입력

- Recents, Projects, Pinned, 보관함과 제목 검색을 제공한다. 목록은 50개씩 추가한다.
- 새 채팅은 이 머신에 실제로 존재하는 절대 경로와 프로젝트를 선택해 만든다.
  프로젝트 추가와 기존 채팅의 프로젝트 소속 이동도 가능하다. 소속 이동은
  작업 폴더·프로젝트 파일·과거 기록의 경로를 옮기지 않는다.
- 고정은 웹 전용 로컬 표시 설정이다. Codex GUI의 고정 목록이나 다른 계정의
  서버 설정을 변경하지 않는다. 보관된 채팅은 고정 목록에서 숨기고 보관함에 표시한다.
- 채팅 메뉴에서 보관·복원·영구 삭제를 확인 후 실행한다. 대상 ID는 확인 창을
  연 시점에 고정된다. 영구 삭제는 하위 대화도 포함하고 되돌릴 수 없다.
- 사용자 메시지와 최종 Markdown 응답을 우선 표시한다. 명령·도구·진행 안내는
  ‘작업 과정’을 펼칠 때 읽고, 긴 명령 출력은 해당 항목을 펼칠 때 한 번 더 읽는다.
- 마지막 **8개 턴**만 먼저 읽는다. 위로 스크롤하거나 ‘이전 메시지 불러오기’를
  누르면 앞선 8개를 추가하고 기존에 보던 위치를 유지한다. 갱신은 최근 부분만 읽는다.
- **Enter**는 진행 중인 턴에 즉시 개입하고, 쉬고 있으면 새 턴을 시작한다.
  **Shift+Enter**는 공식 입력 큐에 추가한다. **Alt+Enter**는 줄바꿈이다.
  한글 IME 조합 중 Enter는 전송하지 않는다. 모바일 키보드의 Shift 구분은 기기마다
  다르므로 화면의 ‘보내기/즉시 개입’과 ‘큐에 추가’ 버튼도 제공한다.

계정 선택은 채팅의 마지막으로 알려진 등록 계정을 우선하고, 없거나 제거됐으면
`default`를 선택한다. 사용자가 선택한 값은 자동 갱신으로 덮어쓰지 않는다.
계정 관리 창의 추가·기기 코드/브라우저 인증·재로그인·기본 지정·등록 해제는 기존
공통 계정 백엔드를 사용한다. 웹 로그인과 Codex 계정 로그인은 별개다.

## 실제 실행과 소유권

`bridge --stdio --web`이 선택 계정별 공식 `codex --no-daemon app-server`에 연결한다.
일반 TUI/메뉴 bridge에는 이 웹 메서드를 노출하지 않는다. 웹은 모델 판단·스케줄러·
자동 계정 교체를 구현하지 않고 공식 프로젝트·턴·큐 API만 호출한다. 이 구현은
공식 runtime **0.169.0**으로 검증했으며 projects/queue의 일부는 experimental API다.

웹에서 시작한 작업은 브라우저와 독립적이다. 탭을 닫거나 새로고침해도 웹 서비스와
공식 app-server가 살아 있으면 작업은 계속된다. 웹 서비스를 중지/업데이트하면
웹 소유 작업도 중단된다. 재개는 사용자가 같은 채팅을 열어 명시적으로 요청한다.
기존 tmux CLI와 GUI는 별개이며 웹 서비스 중지로 종료하지 않는다.

다른 GUI/CLI가 소유한 채팅은 내용 조회와 큐 추가가 가능하다. 그 큐는 **원래 실행
계정**이 처리한다. 별도 stdio 서버는 외부 writer의 진행 중 턴을 steer할 수 없으므로
직접 개입 버튼을 비활성화하고 소유 창에서 해제하도록 안내한다. 로그인 선택만으로
실행 중 인증을 바꾸거나 GUI를 종료하지 않는다. 다른 프로세스가 소유한 하위 채팅이
있으면 상위 보관/삭제도 거부한다. 외부 실행의 수동 읽기에서 나온 `interrupted`는
종료 증거로 사용하지 않고 원래 창의 상태를 확인하도록 표시한다.

모델 입력 전에는 저장된 로그인 revision과 서버의 실제 ChatGPT 사용자·워크스페이스를
비교한다. 로그인 변경을 발견하면 기존 서버의 인증을 교체하지 않고 오류를 표시한다.
알 수 없는 전송 결과는 자동 재시도하지 않는다. 접수 안내는 작업 완료 안내가 아니다.
대화와 큐에서 처리 여부를 먼저 확인한다. 브라우저 재연결도 입력을 재전송하지 않는다.

## 빌드와 실행

공식 Codex CLI, Node 24와 빌드 도구를 준비한다. 개발 중인 Meteor를 먼저 중지한 뒤
제품 저장소에서 빌드한다. 실행 중 Mach-O/웹 번들을 덮어쓰지 않고 새 immutable 설치에 넣는다.

```sh
./build-web.sh
./install.sh --build --web /absolute/path/to/dist/web/bundle
codexm web --no-open
codexm web status
codexm web logs
codexm web stop
codexm web uninstall
```

일반 `web` 실행은 macOS launchd 또는 Linux 사용자 systemd 서비스
`org.codeasy.codexm.web`를 등록하고 시작한다. 별도 state 경로는 충돌 방지를 위한
접미사를 갖는다. 로그아웃/재부팅 후 실행은 OS 사용자 서비스의 로그인·linger 정책을
따른다. `stop`은 자동 시작도 끄고 `web`을 다시 실행하면 활성화한다. `uninstall`은
소유한 서비스 등록만 제거하고 채팅·계정·웹 데이터를 보존한다. Linux의 실제 서비스
실행은 지원되는 사용자 systemd 세션이 필요하다.

기본 주소는 `http://127.0.0.1:4317`이다. 비밀번호가 없으면 일회용 접속 코드로
브라우저 세션을 발급한다. `--no-open`은 URL과 private 코드 파일 경로만 표시한다.
이전 tmux 웹 실행 영수증의 상태 조회/중지도 유지한다.

개발 실행은 제품 저장소의 소스와 Node 24를 사용한다. 영구 서비스와 구분해
default tmux 서버 `codexm` 작업 공간의 `codexm-web-dev` 창에서 실행한다.

```sh
codexm web --dev /absolute/path/to/codexm/web --port 4317 --no-open
```

인증/Origin 검사 없이 리스너를 노출하지 않는다. 외부 접속은 [HTTPS 안내](public-web.md)를
따라 별도 비밀번호와 HTTPS 역방향 프록시를 명시적으로 구성한다.

## 상태와 검증

제품 소스는 `web/`, `internal/nativecli/web_*.go`, `internal/webhost/`에 있다.
`<state_dir>/web-chat/preferences.json`은 고정/직전 웹 계정 표시 정보만 저장하며,
native DB/rollout/writer lock에는 쓰지 않는다. 실제 프로젝트·보관·삭제는 공식 API를 쓴다.
보관 상태 보조 조회만 현재 SQLite WAL을 읽기 전용으로 확인한다.

검증 명령과 목표별 결과는 [웹 핵심 기능 검증 기록](web-chat-core-progress.md)에 있다.
기존 웹의 도입·축소 이력은 Git의 `90853ab` → `de21af4` → `aa68f90`으로 확인할 수 있다.
