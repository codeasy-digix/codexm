# 로컬 웹과 공식 CLI

현재 웹은 채팅 목록과 계정 정보만 관리한다. 이전 관리자·작업 정책·자체 채팅 화면은
제외했다. 실행 흐름은 `채팅 선택 → 계정 선택 → 공식 CLI → CLI 출력/입력 전달`이다.

`codexm web`은 loopback에 웹을 시작한다. 접속 인증·Origin 검사·일회용 DDP ticket은
유지한다. Go bridge의 허용 메서드는 capabilities, snapshot, accounts.refresh,
terminal.open/read/input/close뿐이다. 작업 등록·재배정·관리자 모델 호출은 없다.

선택한 채팅은 `codexm-cli-<id>` tmux 세션에서 공식 CLI로 실행한다. 웹은 그 화면과
스크롤백을 읽고 입력을 붙여넣는다. ANSI 앱을 별도 채팅 데이터로 변환하거나 공식 DB에
메시지를 쓰지 않는다. 화면은 마지막 1,500줄을 표시하며 전체 터미널 조작·추가 기록
탐색은 표시된 `tmux attach -t ...` 명령으로 한다.

웹을 닫거나 bridge가 재시작되어도 tmux와 공식 CLI는 유지된다. 같은 채팅/계정으로
다시 열면 기존 세션을 이용한다. 다른 계정을 선택할 때는 원래 CLI에서 진행 중인
작업을 종료하고 전환한다. 외부 GUI/CLI의 writer는 강제로 제거하지 않는다.
공식 보관/복원 실패 시 오류를 표시하고 새 resume을 실행하지 않는다.

메시지는 문자열 그대로 전달하고 Enter를 누른다. 한글 조합 중 Enter와 Shift+Enter는
전송하지 않는다. Up/Down/Enter/Esc/Tab/Ctrl+C를 지원한다. 명령어·권한 승인·모델
변경 등 실제 동작은 Codex가 처리한다. ‘터미널 종료’는 사용자의 확인 후 해당 tmux만
종료한다. 웹을 중지하는 것과 CLI를 종료하는 것은 별개다.

전송·실행에는 작업 ID를 붙이며 같은 ID의 중복 실행을 거부한다. 불명확한 응답을
자동 재전송하지 않는다. 이 기록에는 입력 본문을 저장하지 않는다. 현재 버전에는
스케줄러·자동 모델 판단·자동 계정 교체·history-sync가 없다.

웹의 개발/검증/설치는 [제품 설치 문서](deployment.md)를 따른다.
