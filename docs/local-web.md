# 로컬 웹과 공식 CLI

이 문서는 선택적인 이전 웹 경로다. 기본 인터페이스는 [Rust TUI](terminal-ui.md)이며,
웹을 설치하거나 실행하지 않아도 채팅 선택과 계정 관리를 모두 사용한다.

이 웹은 채팅 목록과 계정을 관리한다. 이전 관리자·작업 정책·자체 채팅 화면은
제외했다. 실행 흐름은 `채팅 선택 → 계정 선택 → 공식 CLI → CLI 출력/입력 전달`이다.

모바일에서는 먼저 채팅 목록을 화면 높이에 맞춰 표시하고, 채팅을 선택하면 작업 화면을
연다. `← 채팅 목록`으로 돌아오면 검색 조건과 목록의 스크롤 위치를 유지한다. PC는
목록과 작업 화면을 나란히 표시한다. 목록의 긴 제목은 두 줄까지만 표시하며, 선택하면
작업 화면에서 전체 제목을 볼 수 있다.

`codexm web`은 loopback에 웹을 시작한다. 접속 인증·Origin 검사·일회용 DDP ticket은
유지한다. bridge의 허용 메서드는 capabilities, snapshot, accounts.refresh/remove/setDefault,
login.start/status/cancel, terminal.open/read/input/close다. 작업 등록·재배정·관리자 모델 호출은 없다.

채팅을 고르면 마지막으로 확인된 등록 계정을 선택한다. 이전 계정이 없거나 등록 해제됐으면
`default`를 선택한다. 자동 새로고침은 사용자가 직접 고른 계정을 덮어쓰지 않는다.
선택된 계정이 등록 해제되면 기본 계정으로 돌아오며, 기존 CLI는 종료하지 않는다.

계정 화면은 추가·기기 코드/브라우저 인증·재로그인·기본 지정·등록 해제를 제공한다.
임시 `CODEX_HOME`의 인증 전용 공식 app-server에서 로그인 완료와 계정 ID를 확인한
뒤 인증만 저장한다. 다른 계정 ID로 기존 닉네임을 덮어쓰지 않는다. 기본 지정은 명시적인
별도 동작이며 GUI 재실행 후 적용된다. 등록 해제는 인증·기본 인증·대화·작업을 보존한다.
제거한 닉네임은 같은 계정으로 로그인하면 복구되며 과거 worker 정책을 새로 만들지 않는다.
브라우저 인증의 localhost callback은 서버 장비 브라우저에서 사용하고, 다른 기기에서는
기기 코드를 선택한다. 인증 링크·코드는 요청한 브라우저에서만 표시하고 디스크 작업 영수증,
모델, 알림에는 넣지 않는다. 취소·만료·로그아웃·bridge 종료는 소유한 임시 인증 도우미만 정리한다.

외부 접속은 [HTTPS와 웹 로그인](public-web.md)을 추가해 사용한다. Meteor 리스너는
계속 loopback에 있고 공개 Origin과 Host를 정확히 비교한다. 웹 로그인은 네이티브
Codex 로그인과 별개이며, 로그인 전에는 목록·터미널·계정 정보를 조회할 수 없다.

선택한 채팅은 `codexm-cli-<id>` tmux 세션에서 공식 CLI로 실행한다. 웹은 그 화면과
스크롤백을 읽고 입력을 붙여넣는다. ANSI 앱을 별도 채팅 데이터로 변환하거나 공식 DB에
메시지를 쓰지 않는다. 화면은 마지막 1,500줄을 표시하며 전체 터미널 조작·추가 기록
탐색은 표시된 `tmux attach -t ...` 명령으로 한다.

웹을 닫거나 bridge가 재시작되어도 tmux와 공식 CLI는 유지된다. 같은 채팅/계정으로
다시 열면 기존 세션을 이용한다. 다른 계정을 선택할 때는 원래 CLI에서 진행 중인
작업을 종료하고 전환한다. 외부 GUI/CLI의 writer는 강제로 제거하지 않는다.
공식 보관/복원 실패 시 오류를 표시하고 새 resume을 실행하지 않는다.
실패 원인은 스크롤되는 터미널 위에 별도로 표시한다. `Pane is dead`는 종료 결과일 뿐이며,
원래 GUI가 소유한 채팅은 그 GUI에서 보관하거나 세션을 종료해야 한다. ‘다시 시도’는
사용자가 원인을 해결한 뒤 명시적으로 실행하며 입력을 자동으로 다시 보내지 않는다.

메시지는 문자열 그대로 전달하고 Enter를 누른다. 한글 조합 중 Enter와 Shift+Enter는
전송하지 않는다. Up/Down/Enter/Esc/Tab/Ctrl+C를 지원한다. 명령어·권한 승인·모델
변경 등 실제 동작은 Codex가 처리한다. ‘터미널 종료’는 사용자의 확인 후 해당 tmux만
종료한다. 웹을 중지하는 것과 CLI를 종료하는 것은 별개다.

전송·실행에는 작업 ID를 붙이며 같은 ID의 중복 실행을 거부한다. 불명확한 응답을
자동 재전송하지 않는다. 이 기록에는 입력 본문을 저장하지 않는다. 현재 버전에는
스케줄러·자동 모델 판단·자동 계정 교체·history-sync가 없다.

웹의 개발/검증/설치는 [제품 설치 문서](deployment.md)를 따른다.
