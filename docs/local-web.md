# 로컬 채팅 웹

선택적 Meteor + React 화면이다. 기본 CLI/TUI와 macOS 메뉴 앱은 웹·Node 없이
그대로 사용한다. 웹은 **같은 머신의** 채팅과 프로젝트를 보여주며, 다른 장비의
이력을 동기화하거나 가져오지 않는다.

## 화면과 입력

- 전체 채팅은 최근 이용 순이다. 프로젝트 선택기로 좁히거나 제목을 검색할 수 있다.
  목록은 50개씩 추가한다. 선택한 채팅에는 옅은 배경을, 다른 행에는 얇은 테두리를 표시한다.
  각 행의 2×2 버튼으로 고정, 이름 변경, 보관·복원, 복제(Fork)를 선택한다. 고정 해제는
  고정 탭에서 한다. Fork는 저장된 대화로 새 채팅을 만들며 모델 입력을 제출하지 않는다.
  프로젝트로 이동은 채팅 메뉴에 있다. 상단 버튼 또는 macOS `⌘B`, Windows·Linux `Ctrl+B`로
  좌측 목록을 접거나 연다.
- 채팅 주소는 `/chat/<UUID>`다. 새로고침과 브라우저 뒤로·앞으로 이동에서 같은
  채팅을 연다. 기존 웹 세션을 확인하는 동안에는 로그인 폼을 표시하지 않는다.
- 이 머신의 폴더 선택기로 작업 디렉터리를 찾아 새 채팅이나 프로젝트를 만들 수 있다.
  프로젝트 추가와 기존 채팅의 프로젝트 소속 이동도 가능하다. 소속 이동은
  작업 폴더·프로젝트 파일·과거 기록의 경로를 옮기지 않는다.
- 프로젝트와 고정은 같은 머신의 Codex 원본을 읽는다. 기존 GUI의 프로젝트 ID,
  수동 배정·프로젝트 없음과 작업 폴더 연결, 고정 섹션 순서를 반영한다. GUI에 아직
  연결되지 않은 native 프로젝트에는 같은 선택기 안에서 ‘GUI 목록 외’를 표시한다.
  고정 변경은 공식 섹션 API를 사용한다. 보관된 채팅은 보관함에서 조회한다.
- 보관함의 행에서 복원할 수 있다. 보관·복원·영구 삭제는 확인 창을 열 때 정한 채팅에
  적용한다. 채팅 메뉴의 영구 삭제는 하위 대화도 포함한다.
- 사용자 메시지와 최종 Markdown 응답을 우선 표시한다. 명령·도구·진행 안내는
  ‘작업 과정’을 펼칠 때 읽고, 긴 명령 출력은 해당 항목을 펼칠 때 한 번 더 읽는다.
  진행 중인 턴의 공개 진행 안내는 대화 본문에서도 볼 수 있다.
  최종 응답의 Markdown 표는 열 정렬을 반영하며 좁은 화면에서 표 안을 가로로 스크롤할 수 있다.
- 채팅 목록과 입력창 바로 위에서 작업 상태를 표시한다. 웹 실행의 답변은 공식
  App Server의 `item/agentMessage/delta`를 따라 생성되는 동안 표시하며, 완료된
  이력을 읽으면 저장된 답변으로 바꾼다. 승인이나 추가 답변을 기다리는 상태도 표시한다.
- 다른 GUI/CLI의 상태는 열려 있는 writer와 해당 턴의 저장된 시작·종료 기록으로 판단한다.
  창이 열려 있으면 별도로 표시하고, 실행 여부를 확인할 수 없으면 상태 확인 중으로 표시한다.
  다른 창의 답변과 진행 안내는 Codex가 저장한 부분부터 갱신된다.
- 마지막 **8개 턴**만 먼저 읽는다. 위로 스크롤하거나 ‘이전 메시지 불러오기’를
  누르면 앞선 8개를 추가하고 기존에 보던 위치를 유지한다. 갱신은 최근 부분만 읽는다.
- **Enter**는 진행 중인 턴에 즉시 개입하고, 쉬고 있으면 새 턴을 시작한다.
  macOS에서는 **⌘Enter**, Windows와 Linux에서는 **Ctrl+Enter**로 대기열에 추가한다.
  **Shift+Enter**와 **Alt+Enter**는 줄바꿈이다.
  한글 IME 조합 중 Enter는 전송하지 않는다. 모바일에서는 화면의 버튼을 사용할 수 있다.
- 입력창에서 `/`를 치면 `/goal`, `/plan`, `/status`, `/rename`, `/review`, `/compact`, `/exit`가
  표시된다. `/` 뒤에 이름을 입력하면 스킬도 검색되며, `$`는 스킬만 표시한다. 방향키와
  Enter 또는 Tab으로 선택하거나 클릭할 수 있다. `--web-only`에서 `/goal`은 공식 채팅
  목표를 등록하고, `/plan`은 다음 턴에 공식 계획 모드를 적용한다. `/review`는 Git 변경사항과
  기준 브랜치 비교를, `/compact`는 컨텍스트 압축을 요청한다. 두 명령은 웹에서 실행 가능한
  대기 상태의 채팅에서 사용할 수 있다. 채팅별 초안과 선택한 모드·스킬은 브라우저에 저장한다.
- 웹 전용 실행에서 `/exit`를 입력하고 확인하면 현재 채팅의 공식 연결을 해제한다. 실행 중인
  턴은 확인한 ID로 중지하고 대기 입력은 일시중지한다. 이력이 남아 있으므로 데스크톱에서
  같은 채팅을 열 수 있다. 다른 창이 소유한 채팅의 종료는 해당 창에서 실행한다.
- 채팅 제목 옆 헤더에서 계정, 모델, reasoning effort를 선택한다. 모델과 effort는 새 턴에 적용된다. 선택 가능한 조합은
  현재 계정의 공식 모델 목록에서 가져온다. 즉시 개입과 큐는 채팅의 실행 설정으로 처리한다.
- 터미널을 포함해 빌드한 경우 상단 아이콘 또는 macOS `⌘J`, Windows·Linux `Ctrl+J`로 하단에서 로컬 셸을 연다.
  프로젝트 채팅은 작업 폴더에서, 프로젝트 없이 열면 홈 디렉터리에서 시작한다.
  같은 브라우저 탭에서 채팅을 오가거나 패널을 접어도 채팅별 셸과 출력이 유지된다.
  `exit` 또는 종료 버튼으로 해당 셸과 패널을 닫는다. 브라우저 탭의 연결이 끝나면 그 탭의 셸도 종료된다.
  터미널은 브라우저 인증과 일회용 연결권으로 보호되며, 웹 서비스를 실행하는 OS 사용자 권한을 사용한다.
- 헤더 첫 줄에서 계정 선택 왼쪽에 5시간·주간 잔여 한도 바를 위아래로 표시한다.
  공식 사용량을 읽어 최대 1분간 재사용한다. 확인할 수 없는 창은 `—`로 표시한다.
- **설정**에서 화면 테마, 알림, 단축키, 계정 및 로그아웃을 관리한다. 테마의 기본값은
  시스템 설정이다. **설정 → 단축키**에서 키 조합을 직접 눌러 모델 또는 effort에 할당한다.
  초기값은 `⌘⇧1` GPT‑6.2 Sol, `⌘⇧2` GPT‑6.2 Astra, `⌘⇧4` Max, `⌘⇧5` Extra High, `⌘⇧6` High다.
  `⌘⇧0`은 현재 채팅에서 선택한 모델과 effort를 함께 해제하고 채팅 기본값을 쓴다.
  종전 숫자 할당은 `⌘⇧+숫자`로 옮겨 현재 브라우저에서 계속 쓸 수 있다.
  브라우저나 OS가 먼저 처리하는 키는 다른 조합을 지정한다.

계정 선택은 채팅의 마지막으로 알려진 등록 계정을 우선하고, 없거나 제거됐으면
`default`를 선택한다. 사용자가 선택한 값은 자동 갱신으로 덮어쓰지 않는다.
계정 관리 창의 추가·기기 코드/브라우저 인증·재로그인·기본 지정·등록 해제는 기존
공통 계정 백엔드를 사용한다. 웹 로그인과 Codex 계정 로그인은 별개다.

## 실제 실행과 소유권

`bridge --stdio --web`이 선택 계정별 공식 `codex --no-daemon app-server`에 연결한다.
일반 TUI/메뉴 bridge에는 이 웹 메서드를 노출하지 않는다. 웹은 모델 판단·스케줄러·
자동 계정 교체를 구현하지 않고 공식 프로젝트·턴·큐 API만 호출한다. 이 구현은
공식 runtime **0.171.0**으로 검증했으며 projects/queue의 일부는 experimental API다.

웹에서 시작한 작업은 브라우저와 독립적이다. 탭을 닫거나 새로고침해도 웹 서비스와
공식 app-server가 살아 있으면 작업은 계속된다. 웹 서비스를 중지/업데이트하면
웹 소유 작업도 중단된다. 재개는 사용자가 같은 채팅을 열어 명시적으로 요청한다.
기존 tmux CLI와 GUI는 별개이며 웹 서비스 중지로 종료하지 않는다.

다른 GUI/CLI가 소유한 채팅은 내용 조회와 큐 추가가 가능하다. 그 큐는 **원래 실행
계정**이 처리한다. 실행 중인 턴에는 검증된 소유 연결을 사용해 직접 개입한다. 별도
stdio GUI가 소유한 채팅이 쉬고 있음이 확인되면 보내기도 공식 큐를 사용한다. 실행
중인 GUI의 소유 연결에 접근할 수 없으면 설정된 전용 GUI 채팅으로 전달한다. 접수가
확인된 중계 원문은 웹 이력에 사용자 메시지로 표시한다. 로그인 선택만으로 실행 중
인증을 바꾸거나 GUI를 종료하지 않는다. 다른 프로세스가 소유한 하위 채팅이 있으면
상위 보관/삭제도 거부한다. 외부 실행의 수동 읽기에서 나온 `interrupted`는 종료
증거로 사용하지 않고 현재 writer와 턴 기록을 함께 확인한다.

웹 전용 실행은 대기 입력을 이 머신에 저장한다. 진행 중인 턴에서 중지를 누르면 해당
채팅의 대기열도 멈춘다. 이후 추가한 입력과 기존 입력은 탭을 닫거나 서비스를 다시
시작해도 계속 대기하며, ‘대기열 재개’를 눌러야 앞에서부터 실행된다. 중지한 진행 중
목표는 목표 메뉴에서 재개할 수 있다. 대기 입력은 제자리에서 수정하거나 취소해 초안으로
되돌릴 수 있다. 기존 공식 큐에 등록된 입력은 공식 편집·삭제 API를 사용한다.

**설정 → 알림**에서 등록한 브라우저나 PWA는 이 머신의 공식 Codex GUI, CLI, `codex exec`,
CodexM 웹에서 저장된 완료 알림을 받는다. 알림은 앱 아이콘과 `CodexM [채팅 제목]`을
표시한다. 알림을 누르면 해당 채팅으로 이동한다. 웹 서비스는
공식 상태 인덱스와 롤아웃을 읽기 전용으로 확인하며, 내부 중계·하위 작업과 중지된 턴은
제외한다. 브라우저 구독, VAPID 키와 전송 영수증은 웹 서비스의 로컬 상태 디렉터리에 둔다.

모델 입력 전에는 저장된 로그인 revision과 서버의 실제 ChatGPT 사용자·워크스페이스를
비교한다. 로그인 변경을 발견하면 기존 서버의 인증을 교체하지 않고 오류를 표시한다.
알 수 없는 전송 결과는 자동 재시도하지 않는다. 접수 안내는 작업 완료 안내가 아니다.
대화와 큐에서 처리 여부를 먼저 확인한다. 브라우저 재연결도 입력을 재전송하지 않는다.

## 빌드와 실행

공식 Codex CLI, Node 24와 빌드 도구를 준비한다. 개발 중인 Meteor를 먼저 중지한 뒤
제품 저장소에서 빌드한다. 실행 중 Mach-O/웹 번들을 덮어쓰지 않고 새 immutable 설치에 넣는다.
하단 터미널을 포함하려면 같은 OS에서 빌드한 `web_terminal`의 `web-terminal-pty` 실행 파일을
`WEB_TERMINAL_PTY_PATH=/absolute/path/to/web-terminal-pty ./build-web.sh`로 지정한다.

```sh
./build-web.sh
./install.sh --build --web /absolute/path/to/dist/web/bundle
codexm web --no-open
codexm web status
codexm web logs
codexm web stop
codexm web uninstall
```

일반 `web` 실행은 macOS launchd 또는 Linux 사용자 systemd 서비스
`org.codeasy.codexm.web`를 등록하고 시작한다. 별도 state 경로는 충돌 방지를 위한
접미사를 갖는다. 로그아웃/재부팅 후 실행은 OS 사용자 서비스의 로그인·linger 정책을
따른다. `stop`은 자동 시작도 끄고 `web`을 다시 실행하면 활성화한다. `uninstall`은
소유한 서비스 등록만 제거하고 채팅·계정·웹 데이터를 보존한다. Linux의 실제 서비스
실행은 지원되는 사용자 systemd 세션이 필요하다.

### macOS 웹 서비스의 파일 권한

고정된 **CodexM Web.app**이 launchd 작업의 부모로 실행되면 macOS는 그 앱에 웹 서비스의
파일 접근 권한을 부여할 수 있다. 웹에서 시작한 Codex와 터미널이 다운로드 폴더 등 보호된
경로를 사용해야 하는 Mac에서는 앱을 한 번 준비하고 시스템 설정의 **개인정보 보호 및 보안 →
전체 디스크 접근 권한**에서 승인한다.

```sh
./apps/macos/scripts/install-web-host.sh prepare
./apps/macos/scripts/install-web-host.sh activate
```

`prepare`는 설치 경로에 앱을 만들고 기존 앱의 서명을 확인해 재사용한다. 작업과 웹 터미널이
모두 종료된 뒤 `activate`를 실행한다. launchd에 등록한 `bin/codexm-web` 링크가 앱을 가리키고,
다음 서비스 시작부터 앱이 `bin/codexm-web-release`에 연결된 버전을 실행한다. 이후
`install.sh --web`은 버전 링크를 갱신한다. 이 앱에 부여한 파일 권한은 앱 자체를 교체할 때
다시 확인한다. 화면 기록이나 손쉬운 사용 등은 각각의 macOS 설정에서 승인한다.

기본 주소는 `http://127.0.0.1:4317`이다. 비밀번호가 없으면 일회용 접속 코드로
브라우저 세션을 발급한다. `--no-open`은 URL과 private 코드 파일 경로만 표시한다.
이전 tmux 웹 실행 영수증의 상태 조회/중지도 유지한다.

개발 실행은 제품 저장소의 소스와 Node 24를 사용한다. 영구 서비스와 구분해
default tmux 서버 `codexm` 작업 공간의 `codexm-web-dev` 창에서 실행한다.

```sh
codexm web --dev /absolute/path/to/codexm/web --port 4317 --no-open
```

인증/Origin 검사 없이 리스너를 노출하지 않는다. 외부 접속은 [HTTPS 안내](public-web.md)를
따라 별도 비밀번호와 HTTPS 역방향 프록시를 명시적으로 구성한다.

## 상태와 검증

제품 소스는 `web/`, `internal/nativecli/web_*.go`, `internal/webhost/`에 있다.
`<state_dir>/web-chat/preferences.json`은 직전 웹 계정 표시 정보만 사용한다.
예전 웹 고정 값은 보존하지만 현재 고정 목록에 합치거나 native로 자동 이관하지 않는다.
목록·고정·보관과 기존 프로젝트 연결은 현재 SQLite WAL과 GUI 메타데이터를 읽기 전용으로
조회한다. 조회를 위해 native DB/rollout/writer lock을 수정하거나 대화를 실행하지 않는다.
내용 페이지와 명시적인 프로젝트·고정·보관·삭제 변경은 공식 API를 쓴다.
구조와 검증 기준은 [GUI 목록 호환 안내](web-desktop-catalog.md)에 있다.

검증 명령과 목표별 결과는 [웹 핵심 기능 검증 기록](web-chat-core-progress.md)에 있다.
기존 웹의 도입·축소 이력은 Git의 `90853ab` → `de21af4` → `aa68f90`으로 확인할 수 있다.
