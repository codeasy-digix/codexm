# TUI 채팅 모드 검증

2026-10-22. 기준 `e252228`에서 별도 worktree로 구현했다. 전체 관리 화면은
유지하며 선택한 대화의 읽기·입력·갱신 경로를 같은 화면으로 연결했다.

## 결과

- 목록 클릭/Enter와 `/chat`은 채팅 모드를 열고 입력창에 포커스를 준다.
  단순 열람은 공식 대화를 등록하거나 실행하지 않는다.
- Enter와 마우스 전송은 같은 명령 처리를 거친다. 일반 입력만 기존 durable
  `jobs.send`로 보내며 `/account` 같은 관리 명령을 모델에 보내지 않는다.
- 처음 보내는 저장 대화는 같은 thread ID로 metadata 등록한 뒤 전송한다.
  중지나 외부 writer는 초안을 보존하고 필요한 조작을 안내한다.
- 새 작업은 기본적으로 이 TUI의 채팅으로 열린다. 공식 thread ID가 비동기로
  생성되는 동안에도 초안을 유지하고, 생성 이후 같은 작업에 연결한다.
- 최근 대화는 기존 읽기 API로 2초 주기에 갱신한다. 이전 페이지·도구 출력·
  파일 변경·오류를 표시하며, 수동 스크롤과 대화별 초안·입력 기록을 보존한다.
- 늦은 조회/전송/등록 응답은 다른 대화나 미완성 폼을 덮어쓰지 않는다.
  전송 실패 시 초안을 유지하고 불명확한 결과는 operation 조회로 확인한다.
  동일 지시를 자동 재전송하지 않는다.
- F8 필터와 관리 탭, 공식 터미널 계정 선택창의 키보드/마우스 취소는 채팅
  초안을 보존한다. 검색은 관리 목록에 남는다.
- 계정 목록에 각 별칭의 삭제 버튼을 노출했다. 기존 revision과 확인 화면,
  취소 기본 선택 및 관리자/사용 중 계정 보호를 그대로 사용한다. 삭제 범위는
  codexm 등록 해제이며 로그인 파일과 대화 기록을 보존한다.

## 실행한 검사

- `go test -race -p 4 ./...`
- `go vet ./...`
- `CODEXM_NATIVE_TEST=1 CODEXM_BINARY=<검증 바이너리> go test -race
  ./internal/supervisor -run
  'TestOfficialNativeWorkerLifecycleAndWriterLock|TestOfficialCurrentChatRegistrationAndPausedAccountChangePreserveGoal'
  -count=1 -v` — 공식 엔진 두 격리 검사 통과.
- 실제 tmux/PTY의 가짜 RPC에서 17개 검사 통과: 클릭/키보드 채팅 진입,
  Enter 전송과 답변 갱신, 한글 여러 줄 입력, 채팅별 초안/기록, 관리 탭 왕복,
  계정 삭제 확인과 기본 취소, 40×20 화면, `/` 메뉴와 터미널 복사 전환.
  가짜 작업 전송은 명시적으로 입력한 두 번이며 모델 호출은 0회다.
- `git diff --check`

native 검사는 임시 계정 홈·대화·상태 DB를 사용했다. 운영 대화를 재개하거나
실제 계정을 삭제하는 검사는 수행하지 않았다. 검증용 tmux 세션은
`codexm-tui-chat-check-20261022`, `codexm-tui-chat-ui-20261022`이며 완료 후 모두 정리했다.
터미널 캡처와 검사 로그는 로컬
`~/.local/state/codexm/validation/tui-chat-mode-20261022/`에 보관한다.

공식 Codex 전용 명령과 지원하지 않는 승인 형식은 기존 `/open` 경로로 이용한다.
GUI 플러그인과 웹 화면, supervisor의 계정 전환 정책은 변경하지 않는다.
로컬 소스 빌드만 적용하며 릴리스·태그·npm/tap 및 원격 장비 배포는 수행하지 않는다.

## 로컬 적용

구현 커밋 `6ddf8fe`를 main에 병합·푸시한 뒤 `./install.sh --build --web
<기존 웹 번들>`로 로컬 실행 파일을 교체했다. 기존 웹 번들은 같은 digest로
보존했으며 설치된 바이너리의 버전과 웹 번들 검증도 통과했다. 버전은 0.6.2의
로컬 소스 빌드이고 배포 릴리스는 만들지 않았다.

설치 직전/직후 관리 작업 11개의 ID·thread ID·계정·run ID·종류·일시 중지 상태가
동일했다. 목표 예산은 동일하고 사용량은 감소하지 않았다. 설정 내용과 링크,
공용 native auth 링크 및 설치 관측 동안의 파일 내용도 동일했다. 운영 서비스나
작업은 재시작하지 않았다. `installation.json`은 위 private 검증 폴더에 보관한다.

이미 열려 있는 TUI에는 새 프로세스부터 적용되므로 화면을 종료한 뒤 `codexm`을
다시 실행한다. 화면 종료는 기존 관리 작업을 중단하지 않는다. 임시 worktree와
작업 브랜치는 병합 후 정리했다.
