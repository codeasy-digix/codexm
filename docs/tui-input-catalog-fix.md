# TUI 입력 지연과 대화 이름 점검

2026-10-23. 기준 `07b1dad`. 실행 중인 작업·계정·인증과 공식 Codex DB는
보존하며 TUI의 표시·입력 경로만 고친다.

## 확인한 원인

- 공식 SQLite 609개 대화에서 ID와 기록 경로 중복은 없었다. 이름이 없는 84개
  대화가 ID로 표시됐고, 이 중 76개는 하위 에이전트 대화였다. 동기화 서비스는
  별도로 동작 중이지만 ID 표시 자체는 중복 방 생성의 근거가 아니다.
- 긴 답변·도구 출력을 입력/커서 이벤트마다 여러 번 변환·줄바꿈하고 viewport에
  다시 넣었다. 1,000개 메타데이터와 긴 도구 출력의 격리 benchmark에서 키 입력과
  화면 처리 한 번에 약 28.5ms와 19.4MB 할당이 발생했다.
- 대화 본문 클릭이 입력 포커스를 해제해 Enter와 이후 문자가 대화 입력창으로
  전달되지 않았다. 실행이 중지되거나 외부 writer가 있는 안내도 긴 본문에 가려졌다.

## 수정과 검증

1. 실제 대화/상태/너비 변경 때만 대화 문자열과 줄바꿈을 갱신한다. 입력/커서
   이벤트는 준비된 viewport를 사용하고, 레이아웃 측정에서 대화 전체를 렌더하지 않는다.
2. 본문 클릭·스크롤 뒤에도 채팅 입력 포커스를 유지한다. 키보드로 본문에
   이동한 경우에도 문자/Enter가 입력으로 복귀한다. 관리 폼의 키 처리는 유지한다.
3. 접수·오류·중지/로그인/외부 writer 상태를 입력창 가까이 표시하고 초안을 보존한다.
4. 실제 제목은 유지하고, 이름 없는 하위 작업과 일반 대화는 읽기 쉬운 대체
   이름과 원래 ID 검색을 제공한다. 전체 대화는 숨기거나 삭제하지 않는다.
5. 짧은 fixture 외에 긴 도구 출력/큰 목록의 성능 회귀 검사와 Enter 전송을 검증한다.
   전체 race/vet와 필요한 공식 엔진 격리 검사, 실제 tmux/PTY 입력을 확인한다.
6. 별도 worktree에서 검토 후 commit/push하고 로컬 바이너리만 갱신한다. 운영
   서비스·작업·동기화를 중지하거나 원격 장비에 배포하지 않는다. 임시 tmux는 정리한다.

## 확인 결과와 경계

609개 중 실제 name이나 title이 UUID 또는 thread ID인 대화는 0개였다. 비어 있는
제목을 ID로 대신 표시하던 것이 원인이었다. 실제 subagent 84개는 모두 부모 ID가
있고 부모도 로컬에 존재했다. 미명명 대화 84개와 subagent 전체 84개는 서로 다른
집계이며, 그 교집합이 76개다. 새 표시는 `name/title`을 우선하고, 인식한 subagent
메타데이터의 nickname/role을 사용한다. ID와 모든 목록 행은 보존한다.

별도 `codex-history-sync`는 활성화되어 120초 주기로 실행 중이었다. 진단 시 최근
보고는 실제 적용 0, 캐시/보류 601, 이번 충돌 0이었다. 보류는 실행 중 Codex를
보호하는 가드 때문이었다. 캐시/보류는 중복 대화 개수가 아니며 누적 충돌 ledger
7건도 중복 방 개수를 뜻하지 않는다. 로컬 설치 코드는 원래 thread ID를 검증·유지하고
충돌 시 다른 thread ID를 만들지 않는다. 별도 파일 참조 오류도 관측했으나, 다수의
대화가 paginated history여서 rollout 파일 부재만으로 대화 소실을 판정하지 않았다.
본문이나 원격 장비를 대조한 것은 아니므로 다른 ID의 fork 내용까지 중복이 없다고
단정하지 않는다. 동기화 상태와 설정은 변경하지 않았다.

## 검증

- 전체 `go test -race -p 4 ./...`, `go vet ./...`와 두 공식 엔진 격리 검사.
- 같은 synthetic benchmark: 입력/화면 1회 약 28.5ms·19.4MB에서 약
  0.6ms·0.45MB로 감소. 1,000개 목록과 긴 답변/도구 출력 조건이다.
- 실제 tmux/PTY 대용량 fixture의 19개 검사. 목록 1,035개와 도구 출력 30,000줄에서
  본문 클릭 뒤 한글 240자를 포함한 258자 입력이 약 0.5초 내 화면에 반영됐다.
  명시적인 가짜 지시 전송 3건이 정확한 대화에 도착했고 모델 호출은 0회다.
- 입력/붙여넣기/Enter의 포커스 복귀, 보이는 상태 안내, 읽기 전용 하위 작업에서
  부모 대화로 이동, 내용 변경 시 캐시 갱신과 동일 응답의 캐시 재사용을 확인했다.
- 이전 페이지 응답이 폼을 연 동안 도착하는 경우에도 폼을 닫고 실제 본문을 갱신할
  때 스크롤 위치를 보정하도록 회귀 검사를 추가했다.
- 공식 SQLite의 WAL 관측·쓰기 거부·이름 우선순위·선택 컬럼 없는 스키마·ID 보존,
  malformed/다른 JSON source의 오분류 방지를 검사했다.

검증 자료는 `~/.local/state/codexm/validation/tui-input-catalog-20261023/`에 보관한다.
일반 production 대화로 모델 지시를 제출하거나 기존 계정/작업을 재개하지 않았다.
