# TUI 관리 UX 완성 계획

2026-10-22. 기준 소스: `4edf56a` (0.6.2). 웹·플러그인에 있는 관리 기능을
공식 Codex 명령을 수정하지 않고 터미널에서도 조작할 수 있게 한다.

## 완료 조건

1. 작업·계정·사용량·기록·설정·관리자 메뉴를 화면에서 찾고 선택할 수 있다.
   넓은 터미널은 대화 목록과 상세를 나란히, 좁은 터미널은 세로로 표시한다.
2. 마우스 클릭으로 탭·대화·버튼·폼을 선택하고 휠로 목록·본문을 스크롤한다.
   모든 기능에 키보드 경로를 제공한다. 입력창 ↑↓는 입력 기록, Alt+↑↓는
   작업 선택이다. 마우스 보고를 끄고 터미널의 기본 복사 기능을 쓸 수 있다.
3. 계정을 추가·재로그인·취소·등록 삭제하고 native 기본 로그인과 관리자,
   실행 중인 개별 작업의 계정을 구별한다. 최초 실행에서도 로그인 가능하다.
4. 설정은 필드 편집·선택·저장·다시 불러오기를 지원한다. GUI와 같은 revision
   검사를 사용하고 충돌이나 저장 실패 때 초안을 보존한다.
5. 전체/선택 작업 로그를 계정·기간·변경 사유로 걸러 보고, 사용량·회복 시각과
   계정 전환·실행 시간은 읽기 쉬운 형태로 표시한다.
6. 새 채팅/작업/목표/그룹 생성과 기존 대화 등록·해제, 열기·중지·재개·완료·
   계정 변경을 메뉴에서 수행한다. 모델/추론·부모·목표 예산도 명시적으로 설정한다.
   추가 지시·목표 편집과 지원되는 승인/질문 응답을 제공한다.
7. 관리 기능은 기존 Go application/supervisor/settings/accounts 계층을 재사용한다.
   화면 탐색은 모델을 호출하지 않는다. 단순 선택/열람은 작업을 재개하지 않는다.
   사용자 지시는 명시적인 전송 전에는 실행하지 않는다.
8. 기존 대화·목표·사용량·계정·실행 중인 작업을 보존한다. 공식 Codex SQLite는
   읽기만 하고 writer 잠금을 제거하지 않는다. UI 종료는 관리 작업을 유지한다.

## 순서

- 현재 GUI/TUI와 공통 API를 비교한다. 별도 worktree에서 작업한다.
- 공통 관리 호출과 메뉴·레이아웃·마우스 좌표 처리를 추가한다.
- 계정/설정 편집과 작업 폼, 기록 필터·상태 표시를 연결한다.
- 모델을 호출하지 않는 격리된 기능 검사와 실제 PTY/tmux 입력·크기·마우스
  검사를 수행한다. 테스트에서 실제 인증·운영 세션을 변경하지 않는다.
- 전체 race/vet 및 필요한 공식 엔진 격리 검사를 통과한 뒤 commit/push한다.
  검증과 적용 범위는 별도 결과 문서에 실제 증거로 기록한다.

## 보존 원칙

운영 supervisor 재시작, 사용 중인 계정 변경, 대화 동기화 중단은 이 작업에
포함하지 않는다. 테스트 서비스는 이름이 명확한 임시 tmux에서 실행하고 정리한다.
릴리스·태그·npm/tap 배포는 수행하지 않는다.
